模型侧接受内容规格中的候选集合，两个规格使用同一题位，不建立第二套 32 题清单：

| 象限 | 7 道现有题 | 新构念题 | 反向题 |
| --- | --- | --- | --- |
| Mind | M01、M02、M03、M04、M07、M09、M12 | 情绪觉察 | M04、M07 |

合计 32 题，每象限 8 题、2 道反向题；总体反向题 8 / 32，即 25%。新构念题均按正向计分。

模型接受不等于构念覆盖已经验证。以下宽领域只能被克制解释：

- Mind 新题只覆盖“情绪可能影响判断的觉察”，不代表完整测量信念、创造力或 shadow。
- Body 新题只覆盖基础身体在场，不代表健康水平、疾病状态或完整 embodiment。
- Spirit 新题只覆盖可获得的坦诚连接，不代表完整测量共同体、服务或超越。
- Vocation 新题只覆盖资源与协作准备，不代表完整测量金钱、杠杆、legacy 或系统成熟度。

若产品认为上述未覆盖部分属于主测不可缺少的核心构念，则每象限 8 题的限制不成立，应保留 48 题或增加题量，不能用结果文案扩大单题含义。

## 3. 32 题精确计分

### 3.1 单题归一化

每题答案为 1-5 的整数：

```text
normalizedAnswer = reverseScored ? 6 - answer : answer
```

### 3.2 象限 12 题等值分

每象限固定 8 题。设该象限归一化题分总和为 `S_q`：

```text
S_q = sum(normalizedAnswer), range 8..40
E_q = 12 * S_q / 8 = 1.5 * S_q, range 12..60
```

`E_q` 是 12 题等值分。象限状态、象限阶段、整体平均、最低分、最高分、失衡和成熟象限数量全部基于 `E_q`。禁止把 8-40 的原始和直接送入现有 12-60 阈值。

比较前不取整。内部保留精确的 0.5；用户结果页继续不展示原始分或等值分。

### 3.3 象限状态和 1.1-3.3

| E_q 语义阈值 | 状态 | 象限阶段 | 8 题实际 S_q |
| --- | --- | --- | --- |
| 12-18 | unstable | 1.1 | 8-12 |
| 19-24 | unstable | 1.2 | 13-16 |
| 25-28 | forming | 1.3 | 17-18 |
| 29-32 | forming | 2.1 | 19-21 |
| 33-36 | forming | 2.2 | 22-24 |
| 37-44 | grounded | 2.3 | 25-29 |
| 45-48 | grounded | 3.1 | 30-32 |
| 49-54 | mature | 3.2 | 33-36 |
| 55-60 | mature | 3.3 | 37-40 |

代码应使用 `E_q` 的语义阈值；测试应同时锁定 `S_q` 的实际离散边界。由于步长为 1.5，部分整数阈值不可达，例如 28 的相邻实际值是 27 和 28.5。

### 3.4 整体指标

```text
scores = [E_mind, E_body, E_spirit, E_vocation]
averageScore = sum(scores) / 4
minScore = min(scores)
maxScore = max(scores)
imbalanceScore = maxScore - minScore

unstableCount = count(score <= 24)
formingOrBetterCount = count(score >= 25)
groundedOrBetterCount = count(score >= 37)
matureCount = count(score >= 49)
```

`averageScore` 的步长为 0.375，`imbalanceScore` 的步长为 1.5。判定前均不取整。

### 3.5 整体 Human Level

```text
if unstableCount >= 2 or averageScore < 30 or minScore <= 20:
  level = "1.0"
else if (
  averageScore >= 47
  and minScore >= 41
  and imbalanceScore <= 10
  and groundedOrBetterCount == 4
  and matureCount >= 2
):
  level = "3.0"
else:
  level = "2.0"
```

32 题不得放宽 Human 3.0 门槛。离散量尺使 `minScore >= 41` 的最低实际值为 42，`mature >= 49` 的最低实际值为 49.5。

### 3.6 整体 Phase

Human 1.0：

```text
if unstableCount >= 3 or averageScore < 24 or minScore <= 18:
  phase = "1"
else if unstableCount >= 2 or averageScore < 28:
  phase = "2"
else:
  phase = "3"
```

Human 2.0：

```text
if unstableCount >= 1 or averageScore < 36 or imbalanceScore >= 18:
  phase = "1"
else if averageScore < 43 or imbalanceScore >= 11 or groundedOrBetterCount < 2:
  phase = "2"
else:
  phase = "3"
```

Human 3.0：

```text
if minScore < 45 or imbalanceScore >= 8 or matureCount < 3:
  phase = "1"
else if averageScore < 51 or minScore < 49 or imbalanceScore > 6 or matureCount < 4:
  phase = "2"
else:
  phase = "3"
```

Human 3.3 仍要求 `averageScore >= 51`、`minScore >= 49`、`imbalanceScore <= 6`、`matureCount == 4`。

### 3.7 离散临界值

- `imbalanceScore <= 10` 的最大实际通过值是 9；10.5 不通过。
- `imbalanceScore >= 11` 的最小实际触发值是 12；10.5 不触发。
- `imbalanceScore >= 8` 的最小实际触发值是 9。
- `imbalanceScore > 6` 的最小实际触发值是 7.5。
- `minScore >= 49` 和 mature 的最低实际值是 49.5。
- 不使用显示值、epsilon 或四舍五入反推阶段。
- 若配对数据要求改变任何阈值，必须创建新的 assessmentVersion/scoring 快照并重新验证，不能原地调整 `h3-a32-v1`。

## 4. 并列主导和限制象限

32 题更容易出现同分，固定顺序打破平分会产生系统性 Mind/Vocation 偏差。候选版规则为：

```text
dominantQuadrants = all quadrants where E_q == maxScore
weakQuadrants = all quadrants where E_q == minScore
```

- 数组内部按固定象限顺序展示，但顺序不表示优先级。
- 两个或三个象限同分时必须表达为并列。
- 四象限同分时两个数组都包含四象限，解释为“没有识别出单一主导或限制象限”。
- 不得用题目顺序、反向题数量或固定象限顺序选择唯一结果。
- 旧 scalar 字段如为兼容暂时保留，不得用于 32 题用户文案、行动建议或一致率统计。
- 本 draft 只定义精确同分。相差 1.5 是否属于“实质并列”保持未验证；当前不安排配对研究，也不能预先扩大。

## 5. 缺失答案和输入校验

- `h3-a32-v1` 正式计分必须收到冻结版本的完整 32 个题号。
- 每个值必须是 1-5 的整数。
- 缺失任一题时拒绝计分并返回缺失 ID；不得按已答均值计算或自动补 3。
- 多余未知 ID、48/32 交叉提交、版本缺失或版本不匹配时，API 层必须拒绝请求，不能静默忽略。
- 答题中断可以保存部分进度，但部分进度不能生成正式结果。
- 成功结果必须满足 `answeredCount == 32` 且 `missingQuestionIds` 为空。

## 6. 版本和校准状态

### 6.1 版本身份

| 对象 | 标识 | 当前状态 |
| --- | --- | --- |
| 48 题正式基准 | `h3-a48-v1` | `stable`，生产默认 |
| 32 题候选 | `h3-a32-v1` | `draft`，不可公开评分或分享 |
| 48 题历史结果 | `h3-result-v1` | 冻结兼容 |
| 32 题候选结果 | `h3-result-v2` | 规划中；只有候选实现后建立 |
| 内容结构 | `h3-content-schema-v1` | 题目字段不变时可继续使用 |

`assessmentVersion` 绑定题目 ID、顺序、题干、象限、维度、反向标记、等值评分和阈值。题目替换、语义改写、方向变化或阈值变化时必须新建冻结快照，旧版本不能原地修改。

候选状态使用统一 manifest：`draft -> calibrating -> stable -> retired`。

- `draft`：只允许本地数据校验。
- `calibrating`：只允许受控配对测试，不能成为公开默认。
- `stable`：全部 Accuracy-first 门槛、兼容测试和回滚演练通过后，才可进入默认切换评审。
- `retired`：停止新会话，但历史题库、评分、结果和分享解码永久可用。

模型校准状态可作为 manifest/校准报告的细分字段：`not-started`、`content-reviewed`、`paired-validation`、`qualified`、`failed-revise`。当前是 `not-started`。

### 6.2 结果元数据

32 题实现至少携带：

```text
assessmentVersion = h3-a32-v1
contentSchemaVersion
resultVersion = h3-result-v2
assessmentStatus
calibrationStatus
questionCount = 32
questionSetHash
```

并列数组和新构念解释会改变结果结构与内容，因此不得把 32 题结果标记为冻结的 `h3-result-v1`。

### 6.3 历史兼容

- 当前 `v1.<48 digits>` 永久绑定 `h3-a48-v1 + h3-result-v1` 和冻结题序。
- 32 题校准阶段不开放公众分享；内部测试码必须显著标记 candidate。
- 32 题通过后使用版本 envelope，例如 `v2.a32v1.r2.<payload>.<checksum>`，不能只靠答案长度识别版本。
- 旧无版本 localStorage 固定迁移为 `h3-a48-v1`，不能根据届时默认版本猜测。
- 历史结果按记录内 `assessmentVersion + resultVersion` 重建；禁止使用当前默认题库或模板重算。

## 7. Accuracy-first 晋级门槛（Archive / Inactive）

> 本节保留为历史可选方案。产品已取消准确性研究，因此这些门槛不再安排执行，也不能被视为已通过。没有新授权时，32 题不具备晋级 `stable` 的路径。

以下门槛不可相互补偿，必须全部通过：

| 指标 | 最低门槛 | 判定说明 |
| --- | --- | --- |
| 关键构念覆盖 | 通过 | 产品、内容、模型共同确认；单题宽领域不得被结果过度解释。 |

| 主导象限一致/合理并列 | >= 75% | 32 的并列集合包含 48 的主导结果可计为合理并列。 |
| 限制象限一致/合理并列 | >= 75% | 与主导象限分开统计。 |
| 复测稳定性 | 不明显低于 48 | 核心稳定性指标下降不超过 5 个百分点；同时检查置信区间和象限集中误差。 |

只有准确性门槛全部通过后，才评估体验收益：32 题中位完成时长建议至少下降 20%，完成率不低于 48 题。体验收益不能抵消准确性失败。

### 8.6 缺失、非法和跨版本

- 缺 1 题或多题：拒绝评分并返回 missing IDs。
- 值为 0、6、小数、字符串或 null：拒绝并返回 invalid IDs。
- 多余未知题号：拒绝，不静默忽略。
- 32 题答案提交给 `h3-a48-v1`：拒绝。
- 48 题答案提交给 `h3-a32-v1`：拒绝。
- 部分本地进度：可恢复，不可生成正式结果。

### 8.7 48 题永久兼容

- 合法 `v1.<48 digits>` 始终还原相同 48 题答案和结果。
- 旧分享非法长度/字符继续被拒绝。
- 旧无版本进度和结果迁移后固定为 `h3-a48-v1 + h3-result-v1`。
